# 多 Agent 圆桌升级：star 骨架 + 弱去中心化交流 —— 可行性报告

> 版本：v1.1（采纳审查 P0/P1 与设计补充：弱去中心化定位） ｜ 日期：2026-08-24 ｜ 状态：待最终确认
> 背景仓库：https://github.com/silicon-sbt/agent-roundtable-mcp（fork 自 Random-Walk2026/agent_roundtable）

## 1. 问题定义

### 1.1 结构性缺陷

主流 Agent 框架（DSH、Claude Code、Cursor 等）的多 Agent 协作都是 **star（星型）拓扑**：主 Agent 派活给子 Agent，子 Agent 各自执行、各自向主 Agent 汇报，**子 Agent 之间没有对话通道**。证据：

- Claude Code issue #59523：子 Agent 内部没有 Task 工具，多角色编排塌缩为单层。
- Claude Code issue #87761：编排器（orchestrator）会污染"独立"子 Agent 的咨询结果。

结果："多 Agent 协作"实际退化为"一个主 Agent 串行扮演多个角色"。当任务需要**多视角交锋、互相反驳、在争论中收敛**时（调研、方案评审、风险评估），star 拓扑无能为力。

### 1.2 目标（设计定位）

**不需要完全 mesh（去中心化）。目标是一个"star 骨架 + 弱去中心化交流"的增强圆桌**：

- **保留 star 骨架（中心化秩序）**：主 Agent / 主持人保留调度、发言资格裁决、主题控制、汇总与最终结论权——避免多节点自由对话退化为无裁决的"无政府状态"；
- **开放弱去中心化通道（peer 交流）**：子 Agent（专家）之间获得**定向交流能力**——指名回应、引用上一位、受主持人监督的小组讨论；打破"只能向主 Agent 汇报"的死区；
- **中心可观测、可干预**：所有 peer 交流在主 Agent 视野内发生，可被仲裁、回滚、终止。

类比：这不是从"计划经济"一步跳到"自由市场"，而是**"计划 + 市场"的混合**——中心保留宏观调控，节点之间允许自发的横向交易（交流）。

### 1.3 现状基础

本仓库（agent-roundtable-mcp）已实现 **"模拟圆桌"**：LangGraph 状态机内，多个 Persona 按顺序轮流发言，共享消息状态，主持人引导。当前发言 prompt 已强制"回应上一位"，但**没有显式的指名回应通道、没有跨会议记忆、没有小组讨论**。

已解决：多视角交锋、认识论标签、RAG 引用、报告生成、MCP 集成（DSH / Claude Code 双端实测）。

## 2. 架构与方案

### 2.1 目标架构（弱去中心化）

```text
                主 Agent / 主持人（star 中心：调度·裁决·汇总）
                          |            |            |
              [专家 A]──[专家 B]──[专家 C]──[专家 D]   ← 定向 peer 通道（弱去中心化）
                     │  指名回应 / 引用 / 小组讨论    │
              （所有 peer 交流都在中心视野内，可仲裁）
```

- **强通道（中心-节点）**：主 Agent ↔ 各专家（现状，发言/汇报/裁决）；
- **弱通道（节点-节点）**：专家之间的指名回应、引用、受监督的小组讨论（新增）；
- **约束**：主持人裁决"谁有权回应谁"、发言配额、主题漂移惩罚——中心权威不削弱，仅开放横向交流。

### 2.2 技术方案：A′（LangGraph 收敛升级，推荐）

在现有技术栈内实现，保持主持人 supervisor 为 star 中心，只增加弱去中心化能力：

| 能力 | 实现 | 对应目标 |
| --- | --- | --- |
| 指名回应 | 消息携带 `reply_to`（recipient 指针），主持人裁决后按需触发定向发言 | 弱通道 |
| 引用上一位 | 现有 `_recent_messages` 增强为显式引用锚点（引用-回应指针） | 弱通道 |
| 小组讨论 | 主持人从 full set 中划出子集，用 LangGraph `Send` 动态 fan-out 到子图 | 弱通道（受监督） |
| 跨会议记忆 | 每专家 Checkpointer 持久会话（SQLite/内存），记忆按策略检索/摘要注入 | 记忆增强 |
| 强约束 | 主持人 supervisor 节点：发言配额、主题漂移检测、回应资格裁决 | star 骨架 |
| MCP 层 | 新增参数（如 `reply_to`、`breakout` 小组、`memory` 开关），保持字符串/标量类型 | 兼容 DSH |

**不采用**：

- 方案 B（AutoGen/CrewAI）：框架锁定代价大于收益——弱去中心化不需要其完整群聊协议，且会引入第二套运行时；
- 方案 C（外部 MCP 消息总线）：完全 mesh 是过度设计；但保留"记忆规模/发散率达到阈值时再评估"的观察项，不写死否决。

### 2.3 集成路径

| 阶段 | 内容 | 产出/验收闸门 | 工作量 |
| --- | --- | --- | --- |
| 1 | 现状梳理：graph.py 单图 → 拆出 persona 子图接口 | 代码评审通过 | 0.5 天 |
| 2 | 消息模型增加 `reply_to` 指针 + 主持人裁决逻辑 | 指名回应演示用例通过 | 1-1.5 天 |
| 3 | 小组讨论：Send 动态 fan-out 到受监督子图 | 双专家小组讨论用例通过 | 1-1.5 天 |
| 4 | 每专家 Checkpointer 持久记忆 + 检索/摘要注入策略 | 跨会议记忆召回用例通过 | 1.5-2 天 |
| 5 | MCP 层参数扩展 + DSH schema 兼容回归 | schema 10/10 + 全测试通过 | 0.5-1 天 |
| 6 | 验收测试：对比指标 + 失败恢复 + 并发/幂等 | 验收报告通过 | 1-1.5 天 |

合计 **6-8 人日**（比 v1.0 上调，含验收与恢复语义）。

## 3. 验收标准（P0 补）

1. **对比指标**：同一话题下，开启弱去中心化 vs 当前模拟圆桌，度量：分歧可见度（不同观点是否被显式表达）、观点互驳率（发言中引用/反驳他人的比例）、收敛质量（最终总结是否覆盖主要分歧）；
2. **功能验收**：指名回应准确命中目标专家；小组讨论在主持人监督下开始/结束；跨会议记忆可召回且不泄漏无关历史；
3. **失败恢复**：任一专家子图 LLM 调用失败 → 单点重试/跳过并记录，整场状态可回滚到上一提交点（Checkpointer 对账）；
4. **并发与幂等**：MCP 工具重入去重（同 request id 不重复执行）、Checkpointer 写入竞争用事务锁；
5. **成本上限**：单场 token 预算熔断（如默认 ≤ 200k tokens），超限自动终止并给出部分总结。

## 4. 成本与风险

### 4.1 Token 成本（弱去中心化下可控）

- 不共享完整历史：专家记忆按**摘要/检索**注入，而非全量拼接（避免平方级膨胀）；
- 上限机制：预算熔断（见验收 5）、发言配额、历史压缩；
- 相比完整 mesh 的每专家独立全历史，弱去中心化的成本接近现状的 1.5-2 倍（可控）。

### 4.2 风险与缓解

| 风险 | 缓解 |
| --- | --- | --- |
| 记忆污染（陈旧/冲突事实跨会议扩散） | 记忆版本化 + 冲突时标注"待核实"，主持人可否定旧记忆 |
| 幻觉互相放大 | 认识论标签保留 + 主持人强约束 + 引用锚点可追溯 |
| 主题发散 | 主题漂移惩罚 + 主持人议程控制权 |
| 主持人成新瓶颈/幻觉放大器 | 硬编码规则兜底（配额/漂移阈值）+ 主持人仅裁决不发明事实 |
| DSH schema 兼容 | 新增参数一律字符串/标量（沿用 add_personas 的 JSON 字符串模式） |
| MCP 60s 超时 | 调大 toolCallTimeoutMs + 预留异步任务轮询（V3 观察项） |

## 5. 结论与建议

1. **定位明确**：star 骨架 + 弱去中心化——保留中心秩序、开放定向交流。这既解决 star 的死区（子 Agent 无法互相对话），又避免完全 mesh 的无序与成本失控。
2. **路径收敛**：方案 A′（LangGraph 收敛升级）是唯一必要路线；B/C 现阶段不需要，C 留观察项。
3. **最小可行实现**（与圆桌共识一致）：先做 **指名回应端口 + 主持人强约束**，验证"分歧可见度/互驳率"是否真实提升；通过后再加小组讨论与跨会议记忆。
4. **不排期上马的条件**：按验收标准（§3）完成 6 阶段，总投入 6-8 人日。
